# Real framework pilot (WL-02/04/09/10/12/13, WT-01–06)

The Rust fixture renders a genuine Leptos 0.8.2 island to HTML, compiles the same
crate for wasm32, and uses that build's generated exports. The Flutter fixture
uses SDK 3.35.2 at commit 05db9689081f091050f01aed79f04dce0c750154, a loader-only
bootstrap and a Dart runWidget/ViewCollection entrypoint. Actual controls must
respond; engine-import completion alone cannot pass browser acceptance.

The workflow builds packages as archives, installs them into an isolated npm
consumer, then serves the installed public files. This is candidate-package
round-trip evidence, NOT yet remote zed-registry/release publication acceptance.
Source checkouts are build inputs, never browser consumer overrides. Manifest
JSON is generated from actual outputs by the shared Rust build tool and validated
with the installed owls-interfaces package. No new release schema is invented.

A/B are normal navigation without/with preparation; C/D preserve the document
without/with preparation. The exact assigned cohort and disabled-mode overrides
are recorded. Each browser starts with a new context; real mobile-device and
cross-site cache-partition qualification remain separate from these lab tests.

The HTTPS certificate/key are disposable localhost test inputs and must never be
committed or uploaded. Browser ignoreHTTPSErrors is confined to this generated
localhost certificate; no production TLS policy is weakened. CSP allows Wasm
compilation without JavaScript unsafe-eval. Static artifacts are versioned and
served with appropriate MIME; mutable pages/manifests revalidate.

Initial lockfiles are generated by the pinned CI tools and retained as evidence
for review/commit. Until those are committed, the bootstrap run is not described
as a frozen rebuild. Performance observations here are lab data, not a production
20% improvement or fleet-rollout authorization. No field samples are fabricated.
